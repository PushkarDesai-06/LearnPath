LearnPath · Feature plan · Nov 2026

A calmer, faster LearnPath

A Linear inspired redesign of the signed in app and a fresh landing page. Neutral monochrome surfaces, one collapsible sidebar that does the heavy lifting, crisp icons, subtle motion, and clear feedback on every click. This page is the plan only. Nothing in the app has been changed yet.

The small demos on this page are interactive, so try them: collapse the mock sidebar, hover a row and open its 3 dot menu, press Ctrl K, or flip the theme.

01 Principles

What the design should feel like

Quiet by default

Neutral grays carry the whole UI. Contrast and weight create hierarchy, not color. The only gradient is on the actions that matter, so they read as alive.

Every click answers back

A 2px top bar, a pressed state, an optimistic change or a toast. The learner should never wonder if a click registered.

Keyboard first, mouse friendly

Everything reachable from the palette and shortcuts, with hover affordances that never shift layout and always have a touch fallback.

Density with air

Linear style 28 to 36px rows, 13px UI text, generous page margins. Lists over big cards for anything repeated.

Motion explains, never decorates

120 to 280ms, ease out, transform and opacity only. Everything honors prefers-reduced-motion.

Shape over color for state

Statuses are drawn as distinct SVG shapes with a text label nearby. No glowing dots, no colored pills.

Buttons (hover them)

  • Primary: vertical gradient, 1px inner top highlight, hairline ring, and a slow sheen sweep on hover (desktop only). Press scales to 0.97. Pending keeps width, dims the label and shows a spinner so nothing jumps.
  • Secondary: surface fill with an inset hairline. Ghost: transparent until hover. Icon: 28px square, muted icon that brightens on hover.

  • Headings: 600 weight, tight tracking (-0.015em to -0.03em). Numbers use tabular-nums.

Sidebar anatomy, top to bottom

Header

  • Logo tile (gradient) and learner name. Click opens the account menu below it: profile line, Account settings, Theme submenu (System, Light, Dark), Keyboard shortcuts, Log out.
  • Compose button opens New topic (C).

Search field

  • Looks like an input, opens the command palette. Shows Ctrl K (or the Mac symbol on macOS).
  • Collapsed: becomes a search icon with tooltip.

Primary nav

  • Dashboard, Review (flashcards, with a due count chip), Tutor, All topics. Scoped to the active topic.
  • Active row: filled --active background and bright icon. No left accent bar in the sidebar to keep it calm.

Pinned and Recent

  • Pinned lessons (max 10, drag to reorder) and the last 6 opened lessons, across all topics. Synced via the DB.
  • Each row has a 3 dot menu. Groups collapse with a rotating caret and the state is remembered.

Topics tree

  • Each topic shows a mastery ring icon that animates its fill, an expand chevron, and a 3 dot menu.
  • Expanding reveals modules with their status icon; clicking a module scrolls the dashboard to it. The active topic auto expands.
  • Archived topics live in a collapsed Archived group at the bottom (hidden if empty). "New topic" is the last row.

Footer

  • Help menu (opens upward): Keyboard shortcuts, What's new, Send feedback.
  • Theme toggle with a sun to moon morph, and the collapse button whose inner panel animates.

Behaviors

  • Collapse: 248px to a 52px icon rail with tooltips on the right. Toggle with the footer button, [, or Ctrl B. Width animates with transform friendly grid transitions, labels fade before the width shrinks.
  • Hover peek: when collapsed, resting the pointer on the left edge for 300ms slides the full sidebar over the content as a floating layer (Linear style) and it hides on pointer leave.
  • Resize: drag the right edge between 220 and 320px; double click resets. Width and collapsed state persist in cookies so the server renders the right layout with no flash.
  • Mobile (under 768px): the sidebar becomes a sheet opened from a menu button in the page header, with a dimmed backdrop and swipe to close.
  • Page header: 44px bar with breadcrumbs (Topic, Module, Lesson), contextual actions on the right, and a page level 3 dot menu. Breadcrumb segments are links with their own hover state.
  • Content width: dashboard and lists use up to 1040px; lesson reading text stays at about 680px for comfortable line length.
04 Interaction rules

Hover, press, loading, dropdowns

Top loading bar (click any item in the left table of contents)

  • 2px bar fixed to the top of the viewport, a gray to foreground gradient with a soft leading edge. Driven by transform: scaleX so it never causes layout.
  • Starts on any same origin link click (no modifier keys, no target), on programmatic router.push through a shared hook, and on any mutation wrapped in withProgress() (archive, rename, pin, reset, practice submit, generate).
  • Trickles to about 85% with easing, completes when the pathname or search params change or the mutation settles, then fades out. A safety timeout finishes it after 10s so it can never get stuck.
  • Shows only after a 80ms delay so instant prefetched navigations do not flicker.
  • Paired with Next's useLinkStatus for a subtle shimmer on the exact link that was clicked in the sidebar.

Dropdowns (try both buttons)

Scroll so this sits near the bottom of your window and it will flip above.
Opens above when space below is short
  • Radix DropdownMenu with side and align set per trigger: below for header and row menus, above for sidebar footer menus, right for the collapsed rail. avoidCollisions flips to the other side automatically. 6px offset from the trigger.
  • Enter: opacity 0 to 1, scale 0.96 to 1, and a 4px slide from the trigger direction, with transform-origin set from --radix-dropdown-menu-content-transform-origin so it grows out of the button. 160ms ease out. Exit 110ms.
  • Every item has a leading icon, optional trailing shortcut, and submenus open on hover with a 100ms grace triangle. Destructive items sit last, after a separator.
  • The trigger keeps a pressed look (data-state=open) while its menu is open.

Hover and press

  • Hover styles are wrapped in @media (hover: hover) so taps on touch screens never leave things stuck in a hover state.
  • Hover never changes size or position. Rows only change background and icon color; hover reveal actions occupy reserved space.
  • Press: buttons scale to 0.97, rows darken one step (--active). Focus visible: 2px foreground outline, offset 2px, only on keyboard focus.
  • Tooltips: 500ms initial delay, then instant for neighbors (skipDelayDuration), and they show the shortcut. Every icon only button has one.
  • Optimistic updates for pin, unpin, rename, archive and mark for review, with a toast that offers Undo where it makes sense.

06 Dashboard

The topic dashboard

Same data as today's getDashboard, reorganized as a Linear style overview plus a grouped list. The mock in section 03 shows it inside the shell.

Page header

  • Breadcrumb: Topic, Dashboard. Right side: View options, Tutor (secondary), Review with due count, and the topic 3 dot menu.
  • Topic title is double click to rename inline (also from the menu).

Continue card

  • Recommended next lesson with the reason ("Pick up a review" or "Where you left off"), module name, estimated minutes, and the gradient Continue button.
  • Secondary link: "Review 12 flashcards" when cards are due.

Stats row

  • Mastery (animated ring and count up), Lessons mastered, Modules done, Time spent. Each tile has a hover tooltip explaining how it is computed.

Activity and streak new data

  • 12 week monochrome heatmap (opacity steps, never color) from progress events per day. Hover a cell for "Tue, Nov 18 · 3 lessons, 14 answers".
  • Current and best streak beside it. Timezone aware, see Gotchas.

Modules list

  • Grouped list: module header rows (status icon, title, fraction, 3 dot) that collapse with a chevron, and 36px lesson rows (status icon, title, difficulty, minutes, mini mastery bar).
  • Hover reveals Pin and 3 dot. Locked rows are dimmed and not interactive, with a tooltip explaining the unlock rule.
  • Keyboard: J K move the selection, Enter opens, Space peeks, P pins, . opens the row menu. Right click opens the same menu as a context menu.

Lesson peek panel

  • 300 to 360px panel sliding from the right over the list, opened by Space or clicking a row (Enter or double click navigates).
  • Shows module, difficulty, minutes, mastery, objectives, last practiced, and actions: Open lesson, Ask tutor, Make flashcards, 3 dot. Esc closes, J K switch lessons while open.
  • On mobile it becomes a bottom sheet.

View options

  • Dropdown: Group by Module or Status, Hide mastered, Hide locked, Show module summaries. Saved per user in prefs.

Empty, loading, error

  • Skeletons match the new layout row for row. Empty state uses a line icon, one sentence, and one primary action.
  • The TrailRail side rail is dropped; the sidebar tree and the grouped list replace it.

09 Focus mode

Distraction free flows

  • Onboarding and assessment always render in focus mode: no sidebar, a slim top bar with the logo, a step indicator (Describe, Assess, Path), and an Exit button with Esc that confirms if progress would be lost (it is resumable, so the copy says so).
  • Lessons get an optional focus toggle (F, or from the lesson 3 dot): the sidebar slides out, the header thins to breadcrumb and progress, and the reading column centers. State persists per user.
  • Entering and leaving focus animates the sidebar width and content position together (280ms) so it feels like the room got quieter, not like a page reload.
  • Curriculum generation keeps focus mode until the path is ready, then lands on the new dashboard with the sidebar sliding in.
10 Theme

Light and dark

  • next-themes (already a dependency) with attribute="class", default system. Remove the hard coded dark class on <html> and add suppressHydrationWarning.
  • Switch from the account menu, sidebar footer, palette or Ctrl Shift L. The change crossfades using the View Transitions API where supported, instant otherwise.
  • Toaster, markdown prose, code blocks, the mastery rings and the heatmap all read tokens, so they follow the theme.
  • Interactive lesson artifacts: the sandboxed iframe document injects theme tokens on the server. It must be served with the current theme and receive a postMessage when the theme flips (see Gotchas).

16 Gotchas

Things that can bite

  • Rendering must stay side effect free. Pages run on link prefetch, so recording a recent lesson during render would log every prefetched lesson. Recents are recorded from a client effect on mount.
  • Delete versus background workers. A lesson or artifact job may be mid flight. The cascade must remove queued jobs and the workers must drop results whose curriculum no longer exists.
  • Archive fallbacks. Topic scoped pages fall back to the newest curriculum when ?id= is missing; that fallback must ignore archived topics, or the dashboard could open an archived one.
  • Theme flash. next-themes injects its script before paint; the <html> class can no longer be hard coded to dark.
  • Artifact iframes run on an opaque origin with a strict CSP, so they cannot read the parent theme; the theme goes in the document request and later changes go through the existing postMessage bridge.
  • Streak timezones. Day buckets need the learner's timezone (cookie set from the browser), or late night study breaks streaks.
  • Shortcut conflicts. Single key shortcuts must not fire in inputs, the tutor composer, or during flashcard review.
  • Hover only affordances need a visible fallback on touch screens and keyboard focus.
  • Server rendered sidebar freshness. After any mutation call router.refresh(), matching how the topbar refreshes today.
